# 服务器工作区与远程操作指南

更新时间：2026-09-09

本文规定服务器端重建、WiTwin 和离线分析的目录职责与操作顺序。具体主机、端口、
账号和绝对路径必须在目标服务器上重新确认；2026-08 记录的值只适用于当时环境。

## 目录职责

服务器应分开 Git 工程目录和运行时数据目录：

```text
<repo>/                         Git 工程：源码、schema、配置、文档和小型测试夹具
<runtime>/env/                 Python/Conda 环境
<runtime>/tools/               COLMAP 等本机工具
<runtime>/datasets/            原始 session 与不可提交的大型数据
<runtime>/outputs/             深度图、点云、网格和 WiTwin 输出
<runtime>/logs/                完整运行日志
```

原始 session 应设为不可变输入；抽帧、数据库、对齐结果和模型写入派生目录。视频、
深度图、CSI、点云、网格、环境和构建树不得进入普通 Git。

## 每次任务的顺序

1. 确认主机身份、仓库根目录、分支和未提交修改。
2. 检查 GPU、驱动、磁盘余量、Python 环境和所需工具版本。
3. 阅读 `AGENTS.md`、当前总体进展、迁移计划和相关分支状态。
4. 先运行小型只读探针和最小验证，再开始完整重建或仿真。
5. 将完整日志和大型输出写入运行时目录。
6. 将命令、版本、配置、输入校验和、关键指标和结论写入带日期的历史报告。
7. 提交前检查暂存区和忽略文件，确认没有数据、凭据或机器缓存进入 Git。

## 首次迁移必须重新确认

- 目标服务器地址、认证方式和维护责任；
- Git 工程目录、运行时根目录和大容量数据盘；
- 工作分支与固定的仓库、WiTwin Core 和 WiTwin Channel 提交；
- GPU、驱动、CUDA、OptiX/DrJit、Python 和 COLMAP 版本；
- 现有环境能否通过 WiTwin 最小验证和重建回归；
- 日志、缓存和输出的空间上限及停止阈值。

在这些项目完成实测前，不把历史服务器的 RTX、磁盘、路径或软件版本写成当前事实。

## 安全边界

- 不覆盖已有未提交修改，不使用强制 reset、clean 或 checkout。
- 不修改系统 CUDA、系统 Python、共享库和其他项目环境，除非有单独的环境变更计划。
- 不通过删除其他项目、共享缓存或系统文件释放空间。
- 长任务保存命令、日志、退出状态和磁盘余量；失败时保留可恢复现场。
- 文档中不保存密码、私钥、访问令牌或其他凭据。
