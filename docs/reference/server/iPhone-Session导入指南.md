# iPhone Session 服务器导入指南

更新时间：2026-09-09

本文定义 iPhone session 进入服务器重建与 WiTwin 流水线时的长期规则。字段和文件
角色以 [`schemas/session-format/`](../../../schemas/session-format/README.md) 为准；
本文不另建协议副本。

## 输入原则

- 接收完整、不可变、带校验和的 session，而不是单独的视频、点云或网格。
- 保留每个数据源的原始单调时间戳，通过显式映射建立统一时间轴。
- 原始数据和派生结果分目录保存，导入器不得修改输入来通过检查。
- 设备型号、iOS、App、schema、构建提交、装配和采集异常必须可追溯。

## 基础输入

- 后置 RGB 视频或逐帧图像、视频 PTS、方向、编码、分辨率和颜色语义；
- ARKit 相机内参、参考分辨率、tracking state 与 `arkit_world_T_rear_camera`；
- CoreMotion 时间戳、单位、参考系、采样率和缺样信息；
- session 元数据、文件角色、字节数和 SHA-256；
- 启用联合采集时的 UDP 发送日志、CSI 输入及其时钟映射证据。

## LiDAR 扩展输入

具体字段应在实现时加入新版 schema。首版至少需要表达：

- 每个深度或置信度样本的手机单调时间戳、帧标识和对应 RGB/ARFrame；
- 深度图的宽高、像素格式、无效值约定、长度单位和置信度语义；
- 深度相机内参及其参考尺寸，以及深度到 RGB/后置相机的外参；
- 原始、平滑或重采样状态，明确系统做过的过滤和插值；
- `ARMeshAnchor` 或 RoomPlan 输出的坐标系、单位、anchor 变换、顶点、面、分类和版本；
- LiDAR 不可用、降频、掉帧、tracking limited 和重定位区间。

深度、场景网格和 RoomPlan 不是同一种数据。导入器必须根据文件角色分别解析，不能
仅凭扩展名或目录名推断语义。

## 建议落盘结构

```text
<session_id>/
├── raw/                       不可变的手机与 CSI 原始文件
├── import/                    校验、解码和时间映射报告
├── derived/                   抽帧、RGB-D 对齐和质量指标
├── reconstruction/            COLMAP、RGB-D 或 mesh 处理工作区
├── alignment/                 时间与坐标对齐结果
├── witwin/                    WiTwin 场景输入和配置
└── reports/                   可审计结果摘要
```

实际绝对路径由目标服务器的数据盘配置决定，不写死在公共协议或处理代码中。

## 导入检查

1. 校验 manifest、文件大小和 SHA-256，确认原始文件未变。
2. 检查所有时间戳单调性、数据覆盖、缺口以及跨流关联。
3. 验证相机和深度内参、外参、矩阵方向、旋转正交性及长度单位。
4. 检查 RGB/深度分辨率、方向、裁剪和重采样是否与标定匹配。
5. 统计 ARKit、LiDAR、IMU 和 CSI 的有效率、掉帧及质量状态。
6. 输出机器可读报告；失败必须包含文件、字段、时间区间和原因。
7. 检查磁盘预算后才启动抽帧、稠密重建或 WiTwin 长任务。

## 首个 LiDAR session 验收

- 任一 RGB、深度、网格和位姿样本都能回溯到原始文件及手机时间；
- RGB—深度—位姿关联和坐标转换通过合成投影或已知几何测试；
- 米制尺度经过人工尺寸或标定物独立检查；
- 房间模型报告覆盖率、平面误差、孔洞、连通性和坐标对齐误差；
- WiTwin 导出记录场景坐标、单位、材料区域、轨迹和输入校验和；
- 全部命令、代码版本、配置、日志位置和结果摘要可复现。
