重建和离线分析改到服务器运行。本文只维护迁移任务和验收状态；科学问题与实验门槛

## 当前决定与边界

- 带 LiDAR 的具体 iPhone 型号、iOS 版本和存储容量尚待真机确认，不在文档中预设。
- 后置 LiDAR 用于房间几何和扫描质量增强；前置人脸或深度用于人体—手机几何，
  两类传感器的角色、时间戳和坐标系必须分别记录。
- WiTwin、COLMAP 和重建任务以服务器为目标运行环境；2026-08 的 WSL 与服务器验证
  只作为历史证据，不能证明新目标服务器已经可用。
- 现有 Git 分支名 `work/wsl-witwin` 暂时保留。设备迁移完成并确认多端协作方式后，
  再单独决定是否更名，避免把目录整理与 Git 分支迁移混在一起。
- LiDAR 字段尚未进入当前 Session Format 1.4。协议扩展应在采集实现确定后版本化，
  并保持旧 session 可读。

## 工作流 A：LiDAR iPhone 采集端

1. 记录目标设备型号、硬件标识、iOS、可用容量和 LiDAR/RoomPlan/ARKit 能力探针。
2. 明确首版输出：原始 RGB、ARKit 位姿与内参、CoreMotion，以及场景深度、置信度图、
   场景网格或 RoomPlan 结果中实际采用的子集。
3. 为每类 LiDAR 输出定义文件角色、分辨率、单位、时间基、相机标定、坐标系和质量标志。
4. 冻结 RGB—深度—位姿的逐帧关联方式，保存缺帧和降频事实，不做静默插值。
5. 完成静止、移动、遮挡、低纹理和回环扫描的真机验证，并用人工尺寸或标定物检查尺度。

通过标准：一个导出的 LiDAR session 能由离线检查器完整读取；任一深度或网格样本能
追溯到手机时间、相机位姿、标定信息和质量状态，原始数据保持不变。

## 工作流 B：服务器上的重建与 WiTwin

1. 确认目标服务器身份、GPU、驱动、CUDA、磁盘、Git 工程目录和运行时数据目录。
2. 从固定提交恢复 WiTwin Core/Channel 和依赖，运行最小 LOS、CIR、CFR 与梯度验证。
3. 复核 COLMAP 或替代重建工具；历史 South Building 结果只作回归基线。
4. 实现 LiDAR session 导入、完整性检查、坐标变换、RGB/深度对齐和房间模型导出。
5. 将房间模型、手机轨迹、人体几何和 CSI 时间轴放入统一坐标与数据加载接口。
6. 保存环境清单、命令、配置、提交、输入校验和、日志位置和结果摘要。

通过标准：服务器能从不可变的最小 session 生成可审计的米制房间模型，并运行一个
固定 WiTwin 场景；输出可以回溯到代码版本、环境、输入和配置。

## 工作流 C：跨端契约

- 采集端交付版本化 session、文件清单、校验和和能力报告。
- CSI 端交付原始 CSI、包级时间与时钟映射证据。
- 服务器交付导入报告、坐标对齐报告、房间模型、WiTwin 输入和运行报告。
- 公共字段只在 `schemas/session-format/` 定义；App、CSI 端和服务器解析器不维护副本。
- 所有状态都使用“计划、已实现、已验证”三种语义，旧设备结果不得当作新设备验收。

## 文档交付顺序
